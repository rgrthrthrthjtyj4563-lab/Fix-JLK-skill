2. 已解释当前流程和目标流程。
3. 已识别当前实现与方案文档之间的差异。

如果没有方向性歧义，不要为了征询可逆实现细节而停下来，直接按方案实施。

实施时采用小步、可验证、可回滚的改动。每个阶段先写失败测试，再实现最小改动，再运行相关测试。不要在同一个改动中同时重写渲染器、修改 payload、替换模板和降低验证规则。

==================================================
九、目标占位符协议
==================================================

目标语法：

{{kind.path}}

支持：

{{field.meta.product}}
{{block.preface}}
{{repeat.result_sections}}
{{media.overview_bar}}

占位符名称匹配：

\{\{(field|block|repeat|media)\.[a-zA-Z0-9_.-]+\}\}

要求：

1. field 用于标量短文本。
2. block 用于固定位置的段落数组。
3. repeat 用于动态克隆原型块。
4. media 用于图表、图片或表格插入点。
5. 不支持模板表达式、条件语句和任意代码。
6. 必须支持占位符被 Word 拆分到多个 run。
7. 替换时保留首个命中 run 的样式。
8. 不得破坏 drawing、bookmark、field 或其他非文本节点。
9. 渲染后不得残留任何 {{...}}。

动态 repeat 块优先使用明确 bookmark 边界，不再长期依赖扫描下一个 4.x 标题。

==================================================
十、manifest 最小职责
==================================================

manifest 只描述模板契约，不承载业务逻辑。至少包含：

- schema_version
- template_id
- template_type
- template_file
- renderer
- required_payload_paths
- required_singletons
- optional_singletons
- allowed_chart_modes

必须检查：

- schema 版本
- 模板文件存在
- 路径不逃逸
- template_type 匹配
- payload 必需路径
- 必需单例数量
- repeat bookmark 边界
- 必需图表和关系部件

预检输出：

template_preflight.json

错误应包含稳定 code，例如：

- INVALID_MANIFEST
- UNSUPPORTED_SCHEMA_VERSION
- TEMPLATE_TYPE_MISMATCH
- MISSING_PAYLOAD_PATH
- INVALID_PAYLOAD_TYPE
- MISSING_PLACEHOLDER
- DUPLICATE_SINGLETON
- INVALID_PLACEHOLDER
- MISSING_BLOCK_BOUNDARY
- MISSING_CHART_PART
